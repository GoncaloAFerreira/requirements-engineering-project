# 2.1 Requirements notes

## Ambiguity and Missing information:

While making my requirements analysis, I identified some issues with FR04 and FR05. FR04 concerns booking cancellations, but the cancellation deadline is currently unknown. This could cause problems because without a policy users might cancel close to the booking time and staff may also handle cancellations 
inconsistently and facilities could remain unavailable to other users unnecessarily. I also noticed that FR01 and FR05 have similar purposes as both relate to checking bookings or availability, to avoid duplication FR01 should focus on checking whether a facility is available and FR05 should focus on users viewing 
their own existing booking which make both the requirements distinct.

## Conflicts, assumptions and improvements:

One other issue I found was a potential conflict between NFR01 and FR08/FR09 which restricts access to booking information. FR08 and FR09 include staff viewing and modifying bookings this still needs clarification because normal users should only be able to access their own booking information while staff may need 
to access other bookings for managing purposes, but exactly which staff members can view or modify needs confirmation. I also improved NFR05 after understanding that my original requirement measured how quickly a user completed a booking rather the system response time which was basically related to usability not 
performance the requirement is how quickly the software responds not how fast a user can complete a booking. Some of these requirements are still based on assumptions or proposed targets and need confirmation.
